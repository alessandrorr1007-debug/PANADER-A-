# Fase 7.3 — Compras, punto de venta y caja básica
Portal autenticado: alta de proveedores, recepción de compra multilínea, inventario terminado por lote, precio por versión de receta, apertura/cierre de caja y venta multilínea con cuatro métodos informativos. Consultas por empresa/sucursal y RLS del servidor. Se usan RPC ya existentes.
- Cálculos de importes con enteros escalados (redondeo de compra por línea), cantidades y precios verificados por servidor. Venta requiere caja abierta y precio configurado. No se ejecutan pagos reales.
- Owner/admin gestiona proveedores, precios, compras y caja; operator vende; viewer consulta. Se permite cierre de turno aun con suscripción vencida. La UI actual selecciona sucursales activas; cierre de sucursal desactivada requiere otro flujo.
- Historial de últimas 30 compras/ventas. Catálogos paginados, máximo 5000 registros; máximo 100 líneas. Refresco de módulos descarta formularios no guardados. Reintentos de movimientos comerciales conservan UUID en memoria para el mismo payload; verificar historial si respuesta incierta, antes de recargar o repetir con otro payload.
- Tras compra refresca almacén/producción; tras producción refresca inventario terminado. Cierre básico no incluye movimientos manuales ni historial de arqueo. Faltan reportes, administración SaaS, pruebas navegador y conexión real Supabase. No hay facturación fiscal, devoluciones, mermas ni pasarela de pagos.
- Pruebas Node: validación de líneas, precisión de totales, stock, precio y contratos HTTP simulados. CI conserva pruebas SQL de todas las fases.
