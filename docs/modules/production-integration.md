# Fase 7.2 — Integración de recetas y producción
Portal autenticado: catálogo de versiones, creación de recetas con ingredientes dinámicos y rendimiento, selección de versión, vista previa de consumo/costo y confirmación de lote, historial de 30 lotes por sucursal. La vista previa usa enteros escalados para reproducir el redondeo de cantidades del SQL; costos visibles estimados, servidor autoritativo. Se sincronizan inventario y producción tras escrituras. No se conecta a una instancia en esta fase.
- Owner/admin pueden crear versiones; también operator puede producir. Viewer y suscripción vencida solo consulta.
- La confirmación del lote requiere casilla explícita. Se conserva UUID de solicitud en memoria para reintentos idénticos; comprobar historial ante respuesta incierta, especialmente después de recargar o cambiar disponibilidad. El alta de receta aún no es idempotente: verificar versiones antes de repetir.
- Las consultas están limitadas a 5000 registros de catálogo y 100 líneas por receta, con paginación y error en exceso. La vista previa puede estar desactualizada si otro usuario modifica el stock; el servidor verifica y revierte una operación inválida.
- No hay planificación persistente, anulación, mermas ni aprobación de versiones. Pruebas Node de precisión, validación y contratos HTTP simulados; pendiente prueba real en navegador, Auth, Data API y configuración de instancia.
