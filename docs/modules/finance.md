# Fase 5.2 — Caja, precios y reportes
Borrador PostgreSQL posterior a commerce.sql, no desplegado.
- Una caja abierta por sucursal. Propietario/administrador abre, registra ingresos/egresos manuales y cierra; operario registra ventas. Todos los miembros pueden consultar (permisos financieros más finos pendientes).
- Desde esta fase cada venta nueva requiere caja abierta y precio configurado para la versión de receta. Precios en PEN, por empresa y versión, sin edición histórica. Los lotes de versiones diferentes pueden tener precios diferentes. Ventas anteriores a esta fase quedan sin turno; no se asignan retroactivamente.
- Efectivo esperado = apertura + ventas en efectivo + ingresos manuales - egresos manuales. Tarjeta, billetera y transferencia se reportan aparte. Conteo físico menos esperado = diferencia. No se admite egreso superior al efectivo esperado. Apertura, movimientos y cierre son reintentables con misma identidad/payload; no hay edición de cierres.
- Las operaciones usan el mismo bloqueo por empresa de ventas e inventario. Cierre conserva el esperado calculado; las vistas security_invoker respetan RLS. Las compras recibidas no son automáticamente egresos; el pago se debe registrar aparte.
- Reportes diarios por sucursal en zona America/Lima: ventas, unidades, costo referencial de insumos vendidos, margen sobre insumos y compras recibidas. No es utilidad neta ni contabilidad: no incluye IGV, energía, salarios, mermas, gastos devengados o pagos bancarios. Sin facturación SUNAT, devoluciones, pagos parciales o múltiples cajas simultáneas.
- CI ejecuta las pruebas previas de comercio antes de aplicar este esquema (contrato antiguo), y después las de caja y ventas con los nuevos requisitos. Pendientes: pruebas concurrentes, integración de UI real, migraciones oficiales, Auth/Data API y revisión de seguridad en instancia dedicada.
